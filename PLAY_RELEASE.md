# Выпуск в Google Play — бета-тестирование

Пошаговая инструкция для выпуска **Пеле Шаон Луах 1.0.0-beta4** в закрытое (или внутреннее) тестирование Google Play.

## Что уже готово в репозитории

| | Телефон (`:app`) | Часы (`:wear`) |
|---|---|---|
| applicationId | `app.niflaot.peleshaon` | `app.niflaot.peleshaon` (тот же — Play связывает телефон и часы) |
| versionName | `1.0.0-beta4` | `1.0.0-beta4-wear` |
| versionCode | `7` | `100007` (= 100000 + код телефона: у телефона и часов коды обязаны различаться) |
| targetSdk | `36` (требование Play для телефонов с 31.08.2026) | `35` (требование Play для Wear OS) |
| Формат загрузки | `app-release.aab` | `wear-release.aab` |

- **Подпись ключом загрузки** настроена через переменные окружения и секреты GitHub. Если ключа нет, release-сборка остаётся неподписанной, как раньше.
- **CI** (`.github/workflows/build_apk.yml`) собирает оба AAB и выкладывает их артефактами:
  - `Niflaot-phone-release-aab`
  - `Niflaot-wear-release-aab`
  - В шаге «Report release bundle signing» видно, подписаны ли они (`SIGNED` или `UNSIGNED`).
- **Тексты магазина и «Что нового»** лежат в `fastlane/metadata/android/<язык>/` на 5 языках: en-US, ru-RU, uk, de-DE, iw-IL. Они в формате [fastlane supply](https://docs.fastlane.tools/actions/supply/), поэтому их можно вставить вручную или загрузить автоматически.
- **Графика:** значок 512×512 и баннер 1024×500 лежат в `fastlane/metadata/android/en-US/images/`.
- **Политика конфиденциальности** — [PRIVACY_POLICY.md](PRIVACY_POLICY.md), действует с 23.11.2026.

## 1. Ключ загрузки (один раз)

Google Play App Signing хранит ключ подписи приложения у Google, а вы подписываете загрузки своим **ключом загрузки**. `debug.keystore` из репозитория для Play использовать **нельзя**.

```bash
keytool -genkeypair -v -keystore pele-upload.jks -alias pele-upload \
  -keyalg RSA -keysize 4096 -validity 10000
```

Храните `pele-upload.jks` и пароли вне репозитория: в менеджере паролей и в резервной копии. Файлы `*.jks` занесены в `.gitignore`.

### Подпись в GitHub Actions

Откройте Settings → Secrets and variables → Actions → New repository secret и добавьте:

| Секрет | Значение |
|---|---|
| `PELE_UPLOAD_KEYSTORE_BASE64` | `base64 -w0 pele-upload.jks` (на macOS — `base64 -i pele-upload.jks`) |
| `PELE_UPLOAD_STORE_PASSWORD` | пароль хранилища |
| `PELE_UPLOAD_KEY_ALIAS` | `pele-upload` |
| `PELE_UPLOAD_KEY_PASSWORD` | пароль ключа |

Затем запустите workflow «Build Pele Shaon APK» вручную (Run workflow) и скачайте оба AAB. В логе должно быть написано `SIGNED`.

### Подпись на своём компьютере

В `~/.gradle/gradle.properties` (не в репозитории):

```properties
pele.upload.storeFile=/путь/к/pele-upload.jks
pele.upload.storePassword=...
pele.upload.keyAlias=pele-upload
pele.upload.keyPassword=...
```

Затем выполните `gradle :app:bundleRelease :wear:bundleRelease`. Готовые файлы появятся в `app/build/outputs/bundle/release/` и `wear/build/outputs/bundle/release/`.

## 2. Приложение в Play Console

1. **Создать приложение.**
   - Название: «Пеле Шаон Луах».
   - Язык по умолчанию: русский (ru-RU).
   - Тип: приложение, бесплатное.
   - Подтвердите декларации.
2. **Подпись приложения.** Оставьте Play App Signing с ключом, который создаст Google. Ключ загрузки зарегистрируется при первой загрузке AAB.
3. **Wear OS.** Включите форм-фактор в Настройки → Расширенные настройки → Форм-факторы → Wear OS. У часов будут свои дорожки тестирования. Wear-версия проходит отдельную проверку качества Wear OS.

## 3. Содержание приложения (App content)

| Раздел | Ответ |
|---|---|
| Политика конфиденциальности | Публичный HTTPS-адрес: `https://niflaot.mychitas.app/peleshaon/privacy/` (на него же ведёт кнопка в приложении). **Перед отправкой опубликуйте там текущий PRIVACY_POLICY.md.** |
| Доступ к приложению | Все функции доступны без входа |
| Реклама | Нет |
| Возрастной рейтинг | Анкета IARC, категория «Справочник / Образ жизни». Насилия, азартных игр, общения пользователей, покупок нет |
| Целевая аудитория | 13+ (так приложение не попадает под требования программы «Для всей семьи») |
| Безопасность данных (Data safety) | **Данные не собираются и не передаются.** Сети нет (разрешения INTERNET нет). Напоминания, настройки и город хранятся только на устройстве, а данные, которые не покидают устройство, по правилам Play не считаются «собранными». Импорт и экспорт файлов делает сам пользователь через системный выбор файлов |
| Новостное приложение, медицинские и финансовые функции, госприложение | Нет |

### Декларации разрешений

- **`USE_FULL_SCREEN_INTENT`.** Выберите вариант «Будильник» (alarm clock). Будильники приложения показывают полноэкранный экран сигнала.
- **Сервис переднего плана `mediaPlayback`** (`FOREGROUND_SERVICE_MEDIA_PLAYBACK`). Опишите задачу: звук будильника, который пользователь сам включил, до нажатия «Стоп». Приложите короткое видео: будильник звонит, затем пользователь его останавливает.
- **`SCHEDULE_EXACT_ALARM`.** Отдельная декларация не нужна (её требует только `USE_EXACT_ALARM`, которого в приложении нет). Пользователь сам даёт доступ на экране «Разрешения».

## 4. Страница в магазине

Тексты берутся из `fastlane/metadata/android/<язык>/`:

| Поле | Файл | Ограничение |
|---|---|---|
| Название | `title.txt` | ≤ 30 символов |
| Краткое описание | `short_description.txt` | ≤ 80 символов |
| Полное описание | `full_description.txt` | ≤ 4000 символов |

Графика:

- **Значок** — `images/icon.png` (512×512).
- **Баннер** — `images/featureGraphic.png` (1024×500).
- **Скриншоты телефона** — минимум 2, вертикальные, например 1080×1920. Снимите с тестового телефона: часы, календарь с напоминаниями, редактор напоминания, будильник, Шабат.
- **Скриншоты Wear OS** — минимум 1, квадратные, не меньше 384×384, без рамки часов.

Категория: «Образ жизни» (Lifestyle). Контакт: `Office@niflaot.app`.

## 5. Выпуск в тестирование

1. Тестирование → **Внутреннее тестирование** (до 100 тестировщиков, доступно через несколько минут) или **Закрытое тестирование** → Создать выпуск.
2. Загрузите `app-release.aab`. В поле «Что нового» вставьте `changelogs/7.txt` для каждого языка.
3. На дорожке **Wear OS** создайте выпуск и загрузите `wear-release.aab`. «Что нового» — из `changelogs/100007.txt`.
4. Добавьте тестировщиков (список e-mail или Google-группу), сохраните и отправьте на проверку.
5. **Новый личный аккаунт разработчика:** чтобы потом получить доступ к рабочей версии (production), закрытое тестирование должно идти не меньше 14 дней подряд, и всё это время в нём должны участвовать не меньше 12 тестировщиков. Начните закрытое тестирование как можно раньше.

Можно загружать автоматически через fastlane, если создан сервисный аккаунт Play Developer API:

```bash
fastlane supply --aab app/build/outputs/bundle/release/app-release.aab --track internal \
  --package_name app.niflaot.peleshaon --json_key play-api.json
```

## 6. Перед отправкой проверить

- [ ] CI зелёный, в логе — `SIGNED` для обоих AAB.
- [ ] Проверка по [QA_DEVICE_MATRIX.md](QA_DEVICE_MATRIX.md) на телефоне с Android 16 и на часах:
  - [ ] будильник звучит;
  - [ ] будильник молчит в Шабат;
  - [ ] уведомление о напоминании приходит;
  - [ ] импорт выгрузки Google Календаря работает;
  - [ ] экспортированный .ics открывается в Google Календаре.
- [ ] Политика конфиденциальности опубликована по адресу из раздела 3 и совпадает с PRIVACY_POLICY.md.
- [ ] Отчёт Play «Pre-launch report» не содержит сбоев.

## Следующие версии

Для каждой следующей загрузки поднимайте коды версий:

- телефон: `versionCode = N` и `versionName` в `app/build.gradle.kts`;
- часы: `versionCode = 100000 + N` в `wear/build.gradle.kts`.

Вместе с кодами обновите:

- ожидаемые значения в `scripts/check_integrity.py` и в шаге «Validate both phone packages» workflow;
- добавьте `fastlane/metadata/android/<язык>/changelogs/<код>.txt`.
